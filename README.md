## Описание проекта
Приложение «Фото дня» на Flutter, созданное для понимания асинхронного программирования. Оно симулирует загрузку случайных картинок (собак и пейзажей) с задержкой в 2 секунды, показывая пользователю индикатор загрузки, при этом интерфейс приложения не зависает во время процесса.

## Что я изучил в этой лабе:
1. Понял, как работает асинхронность в Dart через объект `Future` и связку ключевых слов `async/await`.
2. Научился делать симуляцию сетевой задержки с помощью `Future.delayed`, чтобы проверять состояния загрузки приложения.
3. Разобрался, как управлять состояниями UI (загрузка, показ ошибки, вывод картинки) с помощью флагов и вызовов `setState()`.
4. Закрепил работу с локальными ресурсами (`assets`) и переключателями `ChoiceChip`.

## Ответы на вопросы к защите:

1. **Что такое Future<T>? Чем отличается от обычного возвращаемого значения?**
`Future<T>` — это объект-обещание. Он говорит программе: «Прямо сейчас результата нет, но он обязательно появится в будущем (через секунду или минуту), и там будут данные типа T». Обычное значение возвращается функцией мгновенно, из-за чего поток может зависнуть, если функция делает тяжелый запрос, а `Future` позволяет программе работать дальше, пока результат "доезжает".

2. **Что делает await? Блокирует ли он весь поток выполнения?**
Ключевое слово `await` заставляет конкретную асинхронную функцию остановиться и подождать, пока выполнится `Future`. При этом весь остальной поток приложения оно вообще не блокирует — интерфейс остается живым, крутилки крутятся, пользователь может кликать на другие кнопки, пока эта конкретная функция ждет свой ответ.

3. **Зачем setState() вызывается дважды в _fetchPhoto()?**
Первый вызов `setState()` нужен в самом начале, чтобы мгновенно включить крутилку (`_isLoading = true`) и сбросить старую картинку. Второй вызов делается уже в самом конце, когда картинка «прилетела» — мы выключаем крутилку (`_isLoading = false`) и заставляем Flutter перерисовать экран, чтобы показать полученное фото.

4. **Почему кнопке передаётся _fetchPhoto без скобок, а не _fetchPhoto()?**
Потому что без скобок мы передаем кнопке *ссылку на саму функцию*, чтобы она запустила её только тогда, когда пользователь реально кликнет на экран. Если поставить скобки `_fetchPhoto()`, то функция выполнится сама по себе прямо в момент сборки интерфейса, еще до всяких кликов.

5. **Чем Image.network() отличается от Image.asset()?**
`Image.network()` берет картинку напрямую из интернета по ссылке (URL), а `Image.asset()` загружает картинку локально, прямо из файлов внутри самого проекта (которые мы прописываем в `pubspec.yaml`).
